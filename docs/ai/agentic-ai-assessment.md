## 1. Executive Summary: What Makes This "Agentic"?

In the enterprise AI domain, "Agentic AI" implies systems capable of autonomous intent decomposition, tool selection, environment interaction, and multi-step goal execution.

**FITMENT.AI is classified as a Level 2 (Directed Tool-Augmented & Orchestrated Multi-Agent) System.**

The platform deliberately enforces **Human-in-the-Loop Governance**: while agents can analyze, extract, score, and query, high-stakes recruitment actions (such as rejecting candidates or releasing offers) require explicit human confirmation.

## 2. Implemented Agentic Capabilities Today

### 2.1 Intent-Driven Database Tool Calling ([`chatbot.py`](file:///e:/Projects/resume-screening-agent/chatbot.py))
The Fitment Assistant functions as a domain-specialized agent with direct tool execution:
- **Entity Resolution Tool**: Resolves ambiguous names or possessive syntax (`"Tarun's score"`) to canonical `candidate_id` records.
- **Relational Query Tools**: Dynamically queries SQLite (`find_candidate_by_name`, `get_candidate_screenings`, `get_follow_ups_overview`).
- **Action Execution Tool with Validation**: Executes recruitment status changes (`update_candidate_status`) directly in the database when instructed by the recruiter, validating against the 11 allowable pipeline stages and logging an audit record.
- **Contextual State Memory**: Maintains active candidate focus across chat turns while allowing effortless global candidate switching.

### 2.2 Directed Multi-Agent Orchestration ([`agent_engine.py`](file:///e:/Projects/resume-screening-agent/agent_engine.py))
The standalone engine coordinates four specialized LLM agents in a sequential pipeline:
1. **JD Analyst Agent**: Extracts core role mandates, must-have skills, and expectations.
2. **Resume & Skill Matcher Agent**: Maps candidate proficiencies and highlights alignment.
3. **RedFlag & Anomaly Hunter Agent**: Identifies employment gaps, rapid job turnover, and skill inconsistencies.
4. **Executive Recruiter & Scorer Agent**: Synthesizes the final scorecard, overall fitment narrative, and interview strategy.

### 2.3 Model Context Protocol (MCP) Server ([`mcp_server.py`](file:///e:/Projects/resume-screening-agent/mcp_server.py))
FITMENT.AI exposes its candidate screening capabilities as a standardized **FastMCP tool** (`screen_candidate`). External LLM agents (e.g. Claude Desktop, Cursor, or enterprise MCP hosts) can invoke FITMENT.AI as a native screening tool.

## 3. Human-in-the-Loop Safeguards (Why We Restrict Full Autonomy)

Full autonomy (Level 3+) is intentionally withheld for ethical, legal, and operational reasons:

1. **Anti-Bias & Compliance**: Fully automated hiring actions without human oversight expose enterprises to regulatory penalties (e.g. EU AI Act, NYC Local Law 144).
2. **Candidate Experience**: Automated rejections generated by autonomous agents risk damaging brand reputation if a rare formatting anomaly caused parsing failure.
3. **Data Protection**: Automatically reaching out to candidates via email or WhatsApp without recruiter review violates privacy policies.

## 4. Autonomous Agent Roadmap (Future Evolution)

| Capability | Current State | Future Level 3 Architecture |
| :--- | :--- | :--- |
| **Candidate Sourcing** | Manual upload of resumes and JDs. | Autonomous ATS sync (Greenhouse, Lever, Workday) via webhooks. |
| **Interview Scheduling** | Recruiter reviews probing questions. | Automated calendar integration (Google Calendar, Outlook) with candidate availability polling. |
| **Candidate Outreach** | Recruiter copies dossier to email. | Draft email generation with recruiter one-click approval before sending. |
| **Real-time Voice Screening** | Static interview probe generation. | Conversational voice agent conducting preliminary 10-minute technical phone screens. |
